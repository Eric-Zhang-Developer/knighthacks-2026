# Bounded challenge rounds

kiro-agent-1: create takes versionId and perspective and returns 201 {sessionId,versionId,perspective}. Round takes no body and returns 200 {round,question,assumption,source}. Answer takes {answer}, at most 8000 nonblank characters, and returns 200 {outcome}. Requests reuse the bounded JSON reader (65536 bytes), session authentication and same-origin mutation checks. Foreign/missing versions and sessions return indistinguishable 404s; invalid inputs 400; unavailable/busy/exhausted operations 409; generation or grounding failures 502; other database failures safe 503.

Sessions bind an immutable version. A conditional session UPDATE atomically reserves a round slot, capped at three, then inserts its round record in the same statement. An outstanding question blocks another round. Answer reservation permits only one concurrent assessment. Repeated answers after completion return 409; no model retry occurs at this endpoint. A unique operation UUID fences completion/cleanup so stale workers cannot change a newer round. Generation and answering have five-minute leases, exceeding the shared provider's maximum ordinary retry/fallback budget. Failed operations consume the slot and attempt atomic failed-round cleanup. If cleanup cannot reach the database, the next round can recover the expired lease; a session with three consumed slots stays exhausted and requires explicit replacement.

Fixture keys are challenge-round-1/2/3 with {question,assumption,source:Claim,test:string|null}, and challenge-answer-1/2/3 with {outcome}. Questions and source text are bounded at 2000 characters; assumptions at 1000. Real source IDs come only from saved neighbor IDs whose current records match the version's corpus. Descriptions (fallback tagline/title) are truncated at 6000 characters as prompt excerpts. Supported claim text must quote every cited excerpt exactly; unknown source IDs are rejected. No sources requires a named nonblank proposed test. That internal test becomes source.text prefixed 'Proposed test: ', label unverified, no citations, preserving the public shape. Returned claims pass shared checkClaims.

Grounding is a dynamic Zod refinement inside shared generate. Its existing two validation attempts implement the required single regeneration; there is no additional retry loop here. Answer assessment uses the stored current question/assumption/source plus the actual answer. No challenge operation inserts or updates idea versions.
